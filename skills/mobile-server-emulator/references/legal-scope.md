# 合规与授权范围

本文件是任务的第一道门。读完后先写结论，再动手。

## 1. 判定顺序

按顺序回答，命中即停：

1. 目标是否**仍在运营**并由厂商提供官方服务器？
   - 是，且没有书面授权 → **停止**。
2. 目标是否已经**官方停服**，且用途是个人或小范围存档研究？
   - 是 → 允许继续，并在案件 `00-scope.md` 写下停服依据（公告、日期、来源链接）。
3. 目标是否是**你拥有的 App、课程靶场、CTF、或书面授权的研究样本**？
   - 是 → 允许继续，并在 `00-scope.md` 写授权边界（可以做什么、不可以外发什么）。
4. 目的是否包含伪造充值、在官方服作弊、公开售卖改包、破坏其他玩家？
   - 是 → **停止**，即使游戏已停服。

写不下来源的「应该停服了」不算依据。先检索公告，再进入 triage。

## 2. 允许

- 已停服作品的协议阅读、最小可启动服务端、本地或小范围存档。
- 自有客户端与自建服务端的联调。
- 书面授权范围内的安全研究，且交付物留在授权方。
- 阅读公开 GitHub preservation 项目的目录结构、许可证和架构，用来对照方法。

## 3. 禁止

- 仍在运营的商业手游未授权私服。
- 伪造订单、无限货币、绕过官方反作弊后连接官方服。
- 把改包、账号、抓包样本公开分发或用于收费。
- 在未授权设备上提取他人账号数据。

## 4. 拒绝时怎么说

说明停在哪一条，并给出可继续的替代：

- 只做界面自动化：使用 `game-automation-scripting`。
- 给自己的游戏做联机：使用 Unity Multiplayer / 自建协议，而不是改官方客户端。
- 只学习公开仓库：打开 [open-source-catalog.md](open-source-catalog.md)，读架构，不对该厂商现网动手。

不要用「教育目的」覆盖第 1 条。

## 5. 写入案件的三行

`cases/<slug>/00-scope.md`：

```text
结论: 允许 | 停止
依据: 停服公告 / 自有 / 授权文件（附链接或路径，不贴密钥）
不做: 充值、官方服、公开分发
```

没有这三行，后续脚本结果都不能当作阶段完成。
